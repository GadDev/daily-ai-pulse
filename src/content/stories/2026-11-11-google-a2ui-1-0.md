The safest way for an agent to build an interface may be to stop it from building the interface.

A2UI 1.0, the first stable release of Google's open generative-UI protocol, lets an agent describe a view using registered components. The host application renders those components natively. The model does not need to write arbitrary HTML, ship a JavaScript bundle or receive every sensitive value displayed on screen.

That separation is the product.

## What changed

Version 1.0 adds a stable protocol, bidirectional function calls, accessibility metadata and extension points. Open-source renderers cover React, Angular and Lit on the web; Flutter across several platforms; SwiftUI on iOS; and Jetpack Compose, which is still moving from 0.9.1 toward 1.0.

Agent SDKs are available for Python, TypeScript and Dart. A2UI can also render inside MCP Apps, allowing the same agent-described view to appear in supported assistants such as Claude and Gemini.

Google names several adopters. Atlassian is using interactive cards when an agent needs a decision inside a Jira work item. Alation renders data feeds and charts in its own application and inside Claude. ByteDance has an A2UI renderer for Lynx and is adapting it to 1.0.

These examples establish implementation activity. They do not independently prove Google's broad claims about latency, reliability or security.

## The protocol narrows the model's authority

An unrestricted model-generated interface can invent controls, leak data into prompts or create a polished path to an action the user did not understand.

A2UI moves important choices back to application code. The host registers the allowed component catalog. It controls how data binds to those components. It can keep sensitive values on the server. It decides what a function call means and whether it is authorized.

That is stronger than asking a model to generate safe frontend code every time. It is not automatically safe.

A model can still choose a misleading component, omit a warning, preselect an option or request a consequential function. A renderer can implement the protocol incorrectly. An extension can widen the surface beyond what reviewers expected.

The security boundary is the combination of component allowlist, schema validation, server-side binding and action policy—not the protocol name.

## Bidirectional calls deserve the most scrutiny

Version 1.0 allows a generated view to call functions, such as checking availability from a reservation picker.

That makes the interface useful. It also joins presentation to action.

Every function should have an explicit input schema, an independent authorization check and a clear confirmation rule. The user should see what will happen before data is sent or state changes. The application should distinguish browsing from booking, drafting from sending and proposing from approving.

Do not infer authority from the fact that the function call came from a native component. The agent still selected and populated that component.

## What teams should test

Build one bounded workflow with a small component catalog. Then test the ugly cases:

- unknown components and unsupported extensions;
- invalid or oversized payloads;
- stale server-bound data;
- accessibility order under streamed updates;
- actions requested before required confirmation;
- the same message rendered by two different clients;
- downgraded clients that support only 0.9.1;
- hostile text inside data fields.

Record the protocol message, renderer version, component chosen, displayed values and resulting function call. A screenshot alone is not enough to audit an interactive agent decision.

## Pulse take

A2UI is promising because it makes the model speak a limited interface language instead of handing it the keys to the browser.

The stable release gives teams something concrete to implement and test across hosts. The hard work remains gloriously conventional: schemas, permissions, confirmation, compatibility and accessible rendering.

That is not a criticism. Agent interfaces need more boring contracts and fewer magical demos.
